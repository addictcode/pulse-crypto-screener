# План работ: ролики и продукт

План для работы без доступа к машине владельца (облачная сессия Claude Code): у каждой задачи есть
цель, шаги, файлы и критерий «готово». Задачи идут по порядку; блоки A и B независимы и могут
идти в разных сессиях. Отметка в чекбоксе ставится в том же PR, который закрывает задачу.

Составлен 1 ноября 2026. Контекст проекта — `README.md`, `video/README.md`, история `git log`.

## Правила для исполнителя

- **Ветка и PR на каждую задачу или группу**, `main` только через PR с зелёным CI. Не пушить в
  `main` напрямую, не мержить самому: мержит владелец.
- **Коммиты по-русски**, в стиле истории (`git log`): заголовок — что изменилось, тело — почему.
  Автор — владелец репозитория; никаких `Co-Authored-By` и «Generated with» в коммитах и PR.
- **Перед коммитом** прогнать то, что задето: `cd backend && ./gradlew build`,
  `cd web && npm test && npx tsc --noEmit && npm run e2e`, `cd video && npx tsc --noEmit`.
- **Честность в контенте.** Только реальные данные и реальные цифры, никаких обещаний прибыли,
  «сигналов, которые угадывают рынок», выдуманных графиков. В каждом ролике и посте —
  «Не финансовый совет». Если данные не сходятся, событие отбрасывается, а не «подправляется».
- **Ролики без привязки:** ни тикера, ни даты, ни времени суток в кадре и в подписи. Их постят
  позже и в любом порядке.
- **Вспышки на склейках остаются** как есть (решение владельца).
- **Рендер в одну вкладку** (`CONCURRENCY=1`, по умолчанию) и `scripts/check.py` после каждого
  ролика: с несколькими вкладками Chrome отдаёт битые кадры-«плитки».
- **Звук не вшивается** трендовый (авторские права, его ставят в TikTok). Свои синтезированные
  эффекты — можно (задача A5).
- Не трогать `web/src/planet.ts` без нужды: у владельца там локальные правки.

## Что облаку недоступно

- Живой стек (Docker, Postgres, туннель) работает на маке владельца. Деплой, миграции на живой
  базе и выгрузка сигналов из неё — только локально.
- `fapi.binance.com` из США отвечает 451. Для свечей использовать архив
  `https://data.binance.vision/data/futures/um/daily/klines/<SYMBOL>/1m/<SYMBOL>-1m-<YYYY-MM-DD>.zip`
  (проверено: доступен, CSV с заголовком). Список символов — S3-листинг
  `https://s3-ap-northeast-1.amazonaws.com/data.binance.vision?delimiter=/&prefix=data/futures/um/daily/klines/`.
  Архив появляется с задержкой около суток.
- Аккаунты, токены, оплата и публикации — только владелец (см. блок C).

## Блок A. Ролики

Сейчас: `video/` на Remotion, 4 шаблона (Event, Guess, Top3, Counter), 153 ролика из 22 событий,
события берутся из локальной базы (`scripts/candidates.json`) и сверяются со свечами.

### A1. Источник событий без базы — архив Binance (~1.5 ч) — [x] сделано

**Цель:** находить реальные резкие движения прямо по архиву свечей, чтобы новые пачки роликов
делались в облаке.

- `video/scripts/archive-events.mjs`: берёт N самых ликвидных USDT-перпетуалов (по сумме
  `quote_volume` за последний доступный день; кэш дневных zip в `video/.cache/`, в `.gitignore`),
  перебирает дни за период (`--days 30`), ищет минуты, где движение за 5 минут (high/low окна)
  ≥ `--min 5`%, отбрасывает свечи новых листингов (меньше 100 минут истории до события) и
  моменты, где цена 5 минут назад вне дневного диапазона (та же логика, что `SignalRules.withinDay`).
- Одно событие на монету в сутки (сильнейшее), окно 45 минут до и 75 после — формат
  `public/events.json` тот же, что у `scripts/events.mjs`. Новые события **дописываются** к
  существующим без дублей (ключ: символ + минута), `id` уникален.
- Флаги: `--days`, `--pairs 120`, `--min 5`, `--max 60`.
- Тест (vitest или node:test) на поиск движений по маленькому синтетическому CSV.

**Готово:** `node scripts/archive-events.mjs --days 30 --max 60` добавляет ≥ 40 новых событий,
сверка свечами из `events.mjs` для них проходит; README описывает оба источника.

### A2. Рендер в GitHub Actions (~1 ч) — [x] сделано

**Цель:** пачка роликов собирается в облаке и скачивается архивом, без мака.

- `.github/workflows/video.yml`, `workflow_dispatch` с входами `templates` (по умолчанию все),
  `max`, `lang` (после A3), `refresh_events` (запустить A1 перед рендером).
- `ubuntu-24.04`, Node 22, Python 3 + numpy для `check.py`, ffmpeg; Chrome — системный
  (`CHROME=$(which google-chrome)`) или `npx @puppeteer/browsers install chrome@stable`.
- Результат: артефакт `pulse-videos-<run>` с `out/*.mp4` и `captions.txt`, хранение 14 дней.
  Тайм-аут джоба с запасом (ролик ~30 с).
- `render.mjs` уже пропускает готовые файлы; в CI каталог чистый — это нормально.

**Готово:** ручной запуск с `max: 6` проходит и даёт скачиваемый архив из 6 роликов без битых
кадров (`check.py` в логе).

### A3. Английская версия (~1.5 ч) — [x] сделано

**Цель:** второй набор роликов для англоязычного аккаунта.

- `lang: 'ru' | 'en'` в пропсах всех шаблонов; все тексты кадров (хуки, развязки, «за 5 минут»,
  уведомление Pulse, концовка, «Пиши в комменты») и подписи постов — в словарь
  `video/src/text.ts` с ключами по языку. Английские тексты пишутся как мемы для англоязычного
  крипто-TikTok, а не дословный перевод (POV, «Nobody: / The market:», «Expectation / Reality»).
- Файлы `out/en/pulse-NNN.mp4` и `out/en/captions.txt` (хэштеги: #crypto #trading #bitcoin
  #altcoins #futures #binance). Нумерация как у русских.
- Шрифты: латиница уже есть в `public/`.

**Готово:** `npm run render -- --lang en --max 8` даёт 8 английских роликов разных шаблонов,
без кириллицы в кадре (проверка: стоп-кадры).

### A4. Новые шаблоны (~1 ч каждый, делать по одному PR) — [x] сделано

Каждый — своя механика и свой вид, чтобы лента не была однотипной. Все на реальных свечах.

1. [x] **«Таймлапс суток»** — сутки минутных свечей за 6 секунд, счётчик времени 00:00→24:00,
   сильнейшая минута подсвечивается и «ставится на паузу» с процентом. Хук: «24 часа за 6 секунд».
2. [x] **«Было / стало»** — экран делится пополам: слева спокойный час до события, справа 5 минут
   движения, общий масштаб цены. Хук: «Одна и та же монета. Разница — 5 минут».
3. [x] **«Объём взорвался»** — столбики объёма во весь экран, последний вырастает в N раз выше
   среднего (N из данных), потом под ним проявляется цена. Хук: «Смотри на объём, не на цену».
4. [x] **«Серия ловушек»** — три коротких события-ловушки подряд (сюжет `trap` из `story.ts`):
   «Пробой… и назад» ×3. Хук: «3 раза за неделю рынок сделал это».
5. [x] **«Пульс рынка»** — тёмный экран, сетка из 30 плиток-монет, плитки вспыхивают зелёным и
   красным по реальным 5-минутным движениям за час; в конце одна плитка увеличивается на весь
   экран с графиком. Без тикеров. Хук: «Так выглядит час на фьючерсах».

Для каждого: композиция в `Root.tsx`, пять хуков и подписей, место в очереди `render.mjs`
(шаблоны по-прежнему чередуются), стоп-кадры в PR.

**Готово:** у каждого шаблона 3 стоп-кадра в описании PR, `check.py` чистый на пробном рендере.

### A5. Свои звуковые эффекты (~1 ч) — [x] сделано

**Готово:** ролик с `--sfx` содержит аудиодорожку (`ffprobe`), эффекты совпадают со склейками.

## Блок B. Продукт (сайт, бэкенд, бот)

### B1. Счётчик посещений без слежки (~2 ч)

- [x] Сделано: ветка `claude/b1-visits`.

**Цель:** видеть воронку TikTok → сайт → терминал → бот, без cookies и сторонних сервисов.

- Миграция `010`: таблица `visit_day (day, page, source, count)`, уникальный ключ
  `(day, page, source)`, upsert с инкрементом.
- `POST /api/hit {page, source}`: страницы из белого списка (`landing`, `app`, `record`, `clip`,
  `bot-click`, `channel-click`), источник — из `utm_source`/`ref`/`document.referrer`,
  нормализованный в короткий список (`tiktok`, `telegram`, `google`, `direct`, `other`). IP и
  user-agent не хранятся. Лимит из `RateLimitFilter` уже действует; плюс не больше одного хита
  страницы в минуту на адрес.
- Фронт: `navigator.sendBeacon` при открытии страниц; в `STANDALONE`-сборке не отправлять.
- Бот: команда `/visits [days]` только для владельца — таблица по дням и шагам воронки.
- Тесты: контроллер (валидация, лимит), репозиторий (upsert), e2e — бикон уходит.

**Готово:** после заходов на три страницы `/visits` показывает их по источникам.

### B2. Кнопки Telegram на сайте (~1 ч)

- [x] Сделано: ветка `claude/b2-telegram-links` (от B1).

- `GET /api/links` → `{bot, channel}` из `PULSE_TELEGRAM_BOT_USERNAME` (или имени из `getMe`)
  и `PULSE_TELEGRAM_CHANNEL`; пустые поля, если не заданы.
- Лендинг (первый экран и финал), `/record/` и кадр `#clip`: кнопки «Сигналы в Telegram» и
  «Канал» со ссылками `https://t.me/<bot>?start=site` / `https://t.me/<channel>`; без настроек
  кнопки не показываются. Клики идут в B1 как `bot-click` / `channel-click`.
- Бот: `/start <источник>` записывает источник в B1.
- Переводы в `locale-ru.ts`, e2e на появление кнопок при заданных ссылках.

**Готово:** с переменными окружения кнопки есть и ведут куда нужно, без них — нет.

### B3. Бюджет скорости в e2e (~45 мин)

- [x] Сделано: ветка `claude/b3-cls-budget` (от B2). Headless Chromium не видит сдвиги от
  `translate`, поэтому откат ловит отдельная проверка свойств анимации, а не сам замер CLS.

- Playwright-тест лендинга в мобильном вьюпорте с замедлением CPU (через CDP) меряет CLS
  (`PerformanceObserver`, `layout-shift`) — падает при CLS ≥ 0.1. Мы уже ловили 0.71 из-за
  анимации через `translate`.

**Готово:** тест зелёный, а с откатом исправления анимации — красный.

### B4. Исследование качества сигналов (~2 ч, только отчёт)

- [x] Сделано: ветка `claude/b4-signal-research`, отчёт `research/signals-2026-10.md`. На
  проверочной половине эффекта нет ни у одной из четырёх гипотез.

**Цель:** честно понять, есть ли у сигналов предсказательная сила, на архиве (A1 даёт загрузчик).

- Скрипт в `research/` (Python или Node): воспроизвести правила PUMP/DUMP/VOLUME из
  `SignalRules` на архиве 60+ дней, исходы через 5/15/60 минут, разбиение на обучающую и
  проверочную половины по времени.
- Проверить 3–5 гипотез, не больше (объём + движение, время суток, тренд старшего ТФ,
  ликвидность). Отчёт `research/signals-YYYY-MM.md`: таблицы, доверительные интервалы,
  вывод «есть/нет эффекта на проверочной половине».
- **Правила сигналов в коде не менять** — только отчёт; решение за владельцем.

**Готово:** отчёт с выводом по каждой гипотезе на проверочной выборке.

## Блок C. Только владелец

Облако это сделать не может (учётки, токены, деньги, живой стек). Когда сделано — передать
значения через `.env` на маке и сказать Claude в локальной сессии.

1. Бот в @BotFather → `PULSE_TELEGRAM_ENABLED=true`, `PULSE_TELEGRAM_TOKEN`,
   `PULSE_TELEGRAM_OWNER_CHAT_ID`, `PULSE_TELEGRAM_OPEN=true`.
2. Канал, бот — его администратор → `PULSE_TELEGRAM_CHANNEL=@...`.
3. Проверка на healthchecks.io (интервал 1 мин) → `PULSE_HEARTBEAT_URL`.
4. По желанию: домен и сервер (Oracle Cloud Free или VPS) → секреты `VPS_HOST`, `VPS_SSH_KEY`,
   `VPS_KNOWN_HOSTS` в GitHub, тогда CI деплоит сам на каждый мерж в `main`.
5. Деплой мержей на живой стек, пока он на маке (локальная сессия).
6. Публикация роликов — вручную, со своим трендовым звуком.

## Порядок и готовность

Рекомендуемый порядок: A1 → A2 → A3 → A6 → A4 (по одному) → A5 → A7 → A8; параллельно
B1 → B2 → B3, затем B4. Оценка: блок A ~12 ч, блок B ~7 ч.

**Полная готовность:** все задачи A и B смержены с зелёным CI; есть артефакт с ≥ 300 RU и
≥ 300 EN роликами без битых кадров и расписание публикаций; на сайте есть счётчик воронки и
кнопки Telegram (включаются переменными из блока C); отчёт B4 лежит в `research/`.
